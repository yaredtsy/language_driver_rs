## 1. What CI must promise

| Promise | Why |
|---|---|
| a change to one language builds and tests **only** that language | otherwise every pull request waits for ty, the TypeScript checker and rust-analyzer |
| a change to `core/` builds and tests **every** language | `core/` is the contract; nothing else catches a break in it |
| there is **one** required check | branch protection needs a job that always reports, even when most jobs were skipped |
| each language passes on Linux, macOS and Windows | that is what an analyzer owes `vnoc` (V-NOC plan `09/06` §2) |

This is rows R12 (CI by path, one `ci-ok` job) and R8 (nightly) of the V-NOC release plan, applied to this repo.

## 2. The jobs, and what starts each one

| Job | Runs | Started by a change under | OS | Cold / warm **[measure]** |
|---|---|---|---|---|
| `changes` | computes which paths changed | always | Linux | seconds |
| `core` | `cargo test`, `clippy -D warnings`, `fmt --check`, `cargo doc` in `core/` | `core/**` | Linux, macOS, Windows | under a minute |
| `<lang>-syntax` | `cargo test -p <lang>-syntax` + clippy + fmt | `languages/<lang>/**`, `core/**` | Linux, macOS, Windows | seconds once cached |
| `<lang>-analysis` | `cargo test -p <lang>-analysis -p <lang>-cli`, the scenarios for that language | `languages/<lang>/**`, `core/**`, `scenarios/**` | Linux, macOS, Windows | minutes |
| `repo` | `scripts/check-all.sh --static`: the `sem.rs` rule, lint blocks equal to the template, no product words, no personal paths, links in `docs/` | always | Linux | seconds |
| `ci-ok` | needs all of the above; passes if each one passed **or was skipped** | always | Linux | — |

`<lang>` is a matrix over `scripts/list-languages.mjs`, so adding a language adds its jobs without editing the workflow.

The syntax and analysis jobs are separate for the reason the PA plan gives: `cargo test -p typescript-syntax` never compiles the checker, so the
common case (an outline fix) is fast.

## 3. The workflow file (shape)

```yaml
# .github/workflows/ci.yml — shape only
on: { pull_request: {}, push: { branches: [main] } }

jobs:
  changes:
    runs-on: ubuntu-latest
    outputs:
      core: ${{ steps.f.outputs.core }}
      languages: ${{ steps.f.outputs.languages }}        # JSON list, e.g. ["typescript"]
    steps:
      - uses: actions/checkout@v4
      - id: f
        run: node scripts/changed-languages.mjs          # compares with the merge base; "core" changed ⇒ every language

  syntax:
    needs: changes
    if: needs.changes.outputs.languages != '[]'
    strategy:
      matrix:
        lang: ${{ fromJSON(needs.changes.outputs.languages) }}
        os: [ubuntu-latest, macos-latest, windows-latest]
    runs-on: ${{ matrix.os }}
    defaults: { run: { working-directory: languages/${{ matrix.lang }} } }
    steps:
      - uses: actions/checkout@v4
      - uses: Swatinem/rust-cache@v2
        with: { workspaces: languages/${{ matrix.lang }} }
      - run: cargo test -p ${{ matrix.lang }}-syntax
      - run: cargo clippy -p ${{ matrix.lang }}-syntax --all-targets -- -D warnings
      - run: cargo fmt --check

  # analysis: the same, with -p <lang>-analysis -p <lang>-cli

  ci-ok:
    needs: [changes, core, syntax, analysis, repo]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - run: |
          # fail if any needed job failed or was cancelled; "skipped" is fine
          echo '${{ toJSON(needs) }}' | node scripts/all-ok.mjs
```

Two things that are easy to get wrong:

- **Do not use the workflow-level `paths:` filter.** A workflow that does not start reports nothing, and a required check that never reports
  blocks the pull request forever. Start the workflow always, and skip *jobs* with `if:`.
- **`ci-ok` needs `if: always()`.** Without it, a skipped dependency skips `ci-ok` too, and a skipped required check counts as passing only
  sometimes. With it, the job always runs and decides for itself.

`-D warnings` is passed per crate (`-p`), never for the whole workspace. In the Python workspace that keeps the vendored ruff's warnings from
failing our build ([`02-workspaces-and-toolchain.md`](02-workspaces-and-toolchain.md) §3).

## 4. Caching

Each workspace has its own `target/`, so each needs its own cache entry; `Swatinem/rust-cache` takes the workspace folder as an input, and keys
the cache by the lockfile and the toolchain. An engine compiles once per pin and is then restored from cache: the engine changes only when
`Cargo.lock` does.

Without the cache, a cold build of ty takes minutes, and the TypeScript checker (about 110,000 lines in one crate) will be similar **[measure in
TS0]**.

## 5. Nightly

`.github/workflows/nightly.yml`, once a day on `main`:

| Step | Catches |
|---|---|
| every language, every OS, **no cache** | a build that only works because of a stale cache |
| the scenarios, twice, comparing the output | non-determinism (hash-map order reaching the output) |
| `cargo tree -d` per workspace | a second copy of `salsa` or of an engine crate creeping in |
| a throwaway crate that depends on each `<lang>-syntax` **by git**, at `main` | the nested-workspace layout stops resolving for a driver ([`02`](02-workspaces-and-toolchain.md) §2) |

On failure it opens (or updates) one issue. It never blocks a pull request.

Not in this repo's CI: building for the eight VS Code targets. That is `vnoc`'s nightly (row R8): it compiles each driver, and so each analyzer,
from source for every target.

## 6. `scripts/check-all.sh`

Everything CI checks, runnable before you push:

```
scripts/check-all.sh                 # every language (slow)
scripts/check-all.sh typescript      # one language
scripts/check-all.sh --static        # only the greps and link checks (seconds)
```

The static checks are the cheap guards for the rules that the compiler cannot see:

| Check | Rule |
|---|---|
| `grep -l "tsrs_\|ruff_\|ty_\|ra_ap_" */src/*.rs` prints only `sem.rs` files | rule 7, one engine module per crate |
| `grep -ri "vnoc\|FileID\|Schema/" core languages/*/crates` finds nothing | rule 1, no product |
| `grep -r "/Users/\|/home/" core languages/*/crates scripts` finds nothing | rule 5, no personal paths |
| `grep -rn "uuid\|fs::write" */src` finds nothing outside `*-cli` | rule 2, never writes, never invents an ID |
| each `languages/*/Cargo.toml` `[workspace.lints]` block equals `_template`'s | one style |
| `cargo tree` in `core/` shows no engine and no `salsa` | `core/` stays engine-free |
