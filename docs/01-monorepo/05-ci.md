## 1. What CI must promise

| Promise | Why |
|---|---|
| a change to one language builds and tests **only** that language | otherwise every pull request waits for ty, the TypeScript checker and rust-analyzer |
| a change to `core/` builds and tests **every** language | `core/` is the contract; nothing else catches a break in it |
| there is **one** required check | branch protection needs a job that always reports, even when most jobs were skipped |
| each language passes on Linux, macOS and Windows | that is what an analyzer owes `vnoc` (V-NOC plan `09/06` §2) |
| a commit is tested **once** per reason: once in its pull request, once on `main` after the merge | a push to a PR branch must not start a second run as a branch push |
| a newer push to a pull request **cancels** the run still going for it; a run on `main` is never cancelled | the matrix is up to 21 jobs, 7 of them on macOS; an old run's answer is worth nothing |
| the lockfiles in git are the ones tested | an engine pin is its lockfile ([`04-engines.md`](04-engines.md)); CI must fail on a stale `Cargo.lock`, not quietly resolve a new one |
| no job runs longer than its timeout | the GitHub default is 6 hours; a hung test on macOS would hold a runner that long |

This is rows R12 (CI by path, one `ci-ok` job) and R8 (nightly) of the V-NOC release plan, applied to this repo. `vnoc`'s
`.github/workflows/ci.yml` solved the same problems first (concurrency, `save-if`, timeouts, `permissions`); this file follows it where
the repos are alike.

## 2. The jobs, and what starts each one

What changed is computed by `scripts/changed-languages.sh <base> <head>`. It prints `core=true|false` and `languages=[…]`:

| A change under | `core` | `languages` |
|---|---|---|
| `core/`, `scripts/`, `.github/`, `rust-toolchain.toml`, `rustfmt.toml`, `clippy.toml`, `.gitattributes` | `true` | every language |
| `scenarios/` | `false` | every language |
| `languages/<lang>/` | `false` | that language |
| `languages/_template/`, `docs/`, top-level `*.md` | `false` | none (only `repo` and `ci-ok` run) |
| no usable base (a new branch, a force push, a run by hand) | `true` | every language |

| Job | Runs | Runs when | OS | Timeout |
|---|---|---|---|---|
| `changes` | `scripts/changed-languages.sh` | always | Linux | 5 min |
| `repo` | `scripts/check-all.sh --static` (§6) | always | Linux | 10 min |
| `core` | `fmt --check`, `clippy -D warnings`, `cargo test`, `cargo doc -D warnings` in `core/` | `core == true` | Linux, macOS, Windows | 20 min |
| `syntax` (matrix `lang × os`) | `fmt --check`, then clippy and `cargo test` for `-p <lang>-syntax` only: it never compiles the type checker | `languages != []` | Linux, macOS, Windows | 30 min |
| `analysis` (matrix `lang × os`) | clippy and `cargo test --no-fail-fast` for `-p <lang>-analysis -p <lang>-cli` (the scenarios are tests of these crates), then `scripts/check-proofs.sh <lang>` | `languages != []` | Linux, macOS, Windows | 60 min **[measure]** a cold Windows build of ty |
| `ci-ok` | `scripts/all-ok.py` on the `needs` context: fails unless every job succeeded or was skipped | always (`if: always()`) | Linux | 5 min |

`check-proofs.sh` exists because rustdoc reports success when a feature-gated doctest is not compiled in: it runs the compile-fail proofs with
the feature `__proof` on and counts them against `proof-doctests.txt`.

The `lang` matrix is the `languages` output, read from the folder by `scripts/list-languages.sh`, so adding a language adds its jobs
without editing the workflow.

The syntax and analysis jobs are separate for the reason the PA plan gives: `cargo test -p typescript-syntax` never compiles the checker, so the
common case (an outline fix) is fast.

## 3. The workflow file

`.github/workflows/ci.yml`. The parts that are easy to get wrong:

```yaml
on:
  pull_request: {}
  push: { branches: [main] }   # a branch is tested through its PR; main after the merge
  workflow_dispatch: {}        # a branch without a PR, by hand (no base: everything runs)

permissions: { contents: read }

concurrency:                   # a newer push to the same PR cancels the older run; main and runs by hand are never cancelled
  group: ${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

- **`push` is for `main` only.** With `push: {}` every push to a PR branch would start two runs, one as a branch push and one as a PR
  update. A branch is tested through its pull request.
- **`concurrency`.** Runs in the same `group` never overlap. For a PR the group is the PR number, so a new push cancels the old run
  (`cancel-in-progress`). For `main` the group is the ref and nothing is cancelled: each merge gets its own complete run, which is
  also the run that saves the caches (§4).
- **Do not use the workflow-level `paths:` filter.** A workflow that does not start reports nothing, and a required check that never reports
  blocks the pull request forever. Start the workflow always, and skip *jobs* with `if:`.
- **`ci-ok` needs `if: always()`.** Without it, a skipped dependency skips `ci-ok` too, and a skipped required check counts as passing only
  sometimes. With it, the job always runs and decides for itself. `ci-ok` needs only `scripts/` from the checkout
  (`sparse-checkout: scripts`).
- **`--locked` on every cargo command** (`clippy`, `test`, `doc`, and the ones in `check-proofs.sh`): a `Cargo.lock` that does not match
  its `Cargo.toml` fails instead of being rewritten in the runner.
- **`-D warnings` is passed per crate (`-p`), never for the whole workspace.** In the Python workspace that keeps the vendored ruff's
  warnings from failing our build ([`02-workspaces-and-toolchain.md`](02-workspaces-and-toolchain.md) §3).
- **The toolchain is installed by a step of its own** (`rustup toolchain install`, which reads `rust-toolchain.toml`) before
  `rust-cache`, instead of leaving it to rustup's implicit install the first time `rustc` runs.

## 4. Caching

Each workspace has its own `target/`, so each needs its own cache entry. One `Swatinem/rust-cache` step per job:

```yaml
- uses: Swatinem/rust-cache@v2
  with:
    workspaces: languages/${{ matrix.lang }}
    key: ${{ matrix.lang }}                         # the matrix row is not in the key by itself
    save-if: ${{ github.ref == 'refs/heads/main' }} # only main saves; pull requests restore
```

How rust-cache and GitHub behave (read in rust-cache's `src/config.ts` and `src/restore.ts` and in GitHub's dependency-caching docs,
2026-11-16):

| Fact | So |
|---|---|
| the key is built from the **job id** (not the matrix row), the runner OS and arch, a hash of the `CARGO*`/`RUST*` env and of every installed `rustc`, then the workspace's `Cargo.toml`s and `Cargo.lock` | without `key:`, `analysis` for Python and for TypeScript on the same OS differ only by the lockfile part |
| on a miss it restores the newest entry matching the key **without the lockfile part** | without `key:`, after an engine bump the Python job can restore TypeScript's `target/` (gigabytes, all useless). `key: ${{ matrix.lang }}` puts the language in the prefix |
| it caches dependencies, not our crates (they are cleaned before saving) | the cache changes only when `Cargo.lock` or the toolchain does, so a PR's own cache buys almost nothing |
| a cache saved by a `pull_request` run belongs to `refs/pull/N/merge` and can be restored only by that PR; a run looks in its own ref, then the base branch, then the default branch | caches saved from `main` serve every PR; caches saved from PRs serve one PR and take space from `main`'s |
| 10 GB per repository; over the limit, the least recently used entries are deleted; an entry not used for 7 days is deleted | up to 21 entries from `main` alone (core × 3 OS, plus 3 languages × 3 OS × syntax/analysis). PR entries on top of those push `main`'s out, and the next run builds the engines cold. **[measure]** the total in Settings → Actions → Caches after the first `main` run with `save-if` |
| `cache-on-failure` defaults to `false` | a failed build saves nothing; leave it |

An engine compiles once per pin and is then restored from cache. Without the cache, a cold build of ty takes minutes, and the TypeScript
checker (about 110,000 lines in one crate) will be similar **[measure in TS0]**.

If the total from the measurement is over 10 GB even with `main` alone saving: `syntax` saves nothing (`save-if: false`) and restores
`analysis`'s entry (`shared-key`), since its dependencies are a subset. Decide after the measurement, not before.

## 5. Nightly (not built)

Planned: `.github/workflows/nightly.yml`, once a day on `main`:

| Step | Catches |
|---|---|
| every language, every OS, **no cache** | a build that only works because of a stale cache |
| the scenarios, twice, comparing the output | non-determinism (hash-map order reaching the output) |
| `cargo tree -d` per workspace | a second copy of `salsa` or of an engine crate creeping in |
| a throwaway crate that depends on each `<lang>-syntax` **by git**, at `main` | the nested-workspace layout stops resolving for a driver ([`02`](02-workspaces-and-toolchain.md) §2) |

On failure it opens (or updates) one issue. It never blocks a pull request.

Until it is built there is **no** `nightly.yml`. A placeholder that runs `echo` every night shows a green nightly that checked nothing.

Not in this repo's CI: building for the eight VS Code targets. That is `vnoc`'s nightly (row R8): it compiles each driver, and so each analyzer,
from source for every target.

## 6. `scripts/check-all.sh`

Everything CI checks, runnable before you push:

```
scripts/check-all.sh                 # every language (slow)
scripts/check-all.sh typescript      # one language
scripts/check-all.sh --static        # only the greps, the cargo trees and the link checks (seconds)
```

The static checks are the cheap guards for the rules that the compiler cannot see (rule numbers are CLAUDE.md's):

| Check | Rule |
|---|---|
| an engine name (`tsrs_`, `ruff_`, `ty_`, `ra_ap_`) appears only in `sem.rs` or files under `sem/` (Python: also `interp/`); none in `core/` | 4 and 5 |
| `vnoc`, `FileID`, `Schema/` appear nowhere in `core/` or `languages/*/crates` | 1 |
| no `/Users/` or `/home/` in `core/`, `languages/*/crates`, `scripts/` | 6 |
| no `fs::write`, `File::create`, `OpenOptions` or `uuid` in library `src/` outside `*-cli` | 2 |
| each `languages/*/Cargo.toml` `[workspace.lints]` block equals `_template`'s, except `unsafe_code` (`forbid` or `deny`); `allow(unsafe_code)` only in `sem` | one style; 4 |
| no `Cargo.toml` at the repo root | layout |
| `cargo tree` in `core/` succeeds and shows no engine and no `salsa` | 5 |
| `cargo tree -p rust-syntax` has `ra_ap_syntax` and no `salsa`, `ra_ap_hir`, `ra_ap_ide` | the fast crate stays fast (RS1 §7) |
| relative links in `docs/`, `languages/`, `scenarios/` and the top-level `*.md` files resolve | — |

A `cargo tree` check must fail when `cargo tree` itself fails: an empty output from a failed command looks like "no engine found".

## 7. Review of `ci.yml` (2026-11-16)

What was right already: `push` only on `main`, so a PR is not run twice; no workflow-level `paths:`; one `ci-ok` with `if: always()`;
`fail-fast: false`; `-D warnings` per crate; the changes script falls back to "everything" when the base is unusable.

What was wrong, and the steps that fix it. Each step is one commit; run `scripts/check-all.sh --static` before each, and push the branch as
a PR so the new `ci.yml` runs on itself.

| Step | File | Change | Why (section) |
|---|---|---|---|
| C1 | `ci.yml` | add `concurrency` (§3), `permissions: { contents: read }`, `workflow_dispatch: {}` | superseded PR runs kept going; the token had the repo's default rights; a branch without a PR could not be run |
| C2 | `ci.yml` | `timeout-minutes` on every job (§2's column) | the default is 6 hours |
| C3 | `ci.yml` | every `rust-cache` step: `key:` (`core`, or `${{ matrix.lang }}`) and `save-if: ${{ github.ref == 'refs/heads/main' }}` | the cross-language restore and the 10 GB limit (§4) |
| C4 | `ci.yml`, `check-proofs.sh`, `check-all.sh` | `--locked` on every `cargo clippy`, `cargo test`, `cargo doc`, `cargo tree` | a stale lockfile passed (§3) |
| C5 | `ci.yml` | a `rustup toolchain install` step before `rust-cache` in `core`, `syntax`, `analysis`; `ci-ok` checks out with `sparse-checkout: scripts` | §3 |
| C6 | `changed-languages.sh` | `git diff --no-renames --name-only` | with rename detection a file moved out of `languages/<lang>/` lists only its new path, and `<lang>` is not tested |
| C7 | `check-all.sh` | the `core` `cargo tree` check fails when `cargo tree` fails, as the `rust-syntax` check next to it does | §6; seen 2026-11-16: run with no `cargo` on `PATH`, the `core` check passed and only the `rust-syntax` one failed |
| C8 | `nightly.yml` | delete it until §5 is built | §5 |

The proof for the steps: on the PR, `ci-ok` is green with every language running (the PR touches `.github/` and `scripts/`, so everything
runs); a second push to the PR while the first run is going cancels the first; after the merge, the `main` run saves the caches and
Settings → Actions → Caches shows one entry per job, language and OS, with the size noted in §4.

Not done, on purpose: pinning actions to commit SHAs and Dependabot for them, as `vnoc` does. Worth it once the repo is public or has a
second person; until then it is churn.
