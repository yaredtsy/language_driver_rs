# TypeScript and JavaScript: the policy table

What the analyzer draws, and what it does not, for each feature of the language. **Every row names a fixture** and the entries built from it, and has a
snapshot of what they give: the tree and every edge, in `crates/typescript-analysis/tests/snapshots/policy/<row>.txt`. Changing a row is a policy change:
the fixture and its snapshot change in the same pull request, and the version takes a minor step (`docs/01-monorepo/06-versions-and-vnoc.md`).

The test is `crates/typescript-analysis/tests/policy.rs`. It reads this file, so **a row without a fixture, a fixture that is not there, a row without a
snapshot and a snapshot of no row each fail**, and every row's snapshot is compared with what the analyzer gives now. The last cell of a row is read by
the test: the project's folder under `tests/`, a file of it, and the qualnames to build, each in backticks (a row with the folder alone names the outline's
fixtures, a rule of the outline and not of the calls). Write the expected text by hand before running; bless it (`ANALYZER_BLESS=1`) only to write
a snapshot you then review.

A snapshot is, for each entry: the tree (the defs of the project only), then every edge of the graph as `from | callee text | what it is`, grouped by the def
the edge leaves and in source order inside it, then the counters of what no edge covers when any is above 0. `external`, `unresolved` and the counters are in
the edges, not in the tree.

This table is the contract of `typescript-v0.2.0`. The plan's version is `docs/03-typescript/06-ts4-calls.md` §5; the engine's side of each row (what
the checker answers, and where it differs) is in `ENGINE.md`.

| Row | Feature | Phase-1 policy | Fixture |
|---|---|---|---|
| `def` | what is a def | TS1 §2 | `../../typescript-syntax/tests/fixtures` |
| `site` | what is a call site | §3 above | `policy` `src/sites.ts` `sites` |
| `anonymous` | anonymous functions | their calls belong to the enclosing def, at their source position | `policy` `src/callbacks.ts` `callbacks` |
| `nested` | named nested functions | their own def; appear where they are **called**, not where they are declared | `policy` `src/nested_calls.ts` `nested` `declaredNotCalled` |
| `branches` | `if`, `switch`, `?:`, `&&`, loops, `try` | every call expression in the body is a site, whatever branch it is in. No condition is evaluated | `policy` `src/branches.ts` `branches` |
| `class-instance` | a call on a **class** instance (`w: JsonWriter`) | that class's method (or the inherited one, where it is declared) | `policy` `src/method_on_class.ts` `onClass` |
| `interface` | a call through an **interface** or abstract method (`w: Writer`) | the interface's method signature: a leaf with no body. **Not** the implementations | `policy` `src/interface_dispatch.ts` `viaInterface` |
| `union` | a **union** receiver (`w: JsonWriter \| CsvWriter`) | one target per member that declares the method. This **is** the checker's answer: the union property's symbol holds every member's declarations; only the engine's call hierarchy misses it (it follows `value_declaration`, which is empty when members differ), so `sem` reads the symbol's declarations. A declaration with nothing to enter (a member of type `any`, a function type) adds `Unknown(union_receiver)`, so the answer is never mistaken for complete | `policy` `src/union_receiver.ts` `viaUnion` `viaUnionWithFunction` |
| `overloads` | overloads | the implementation | `policy` `src/overloads.ts` `usesOverload` |
| `generics` | generics | the generic declaration; type arguments are ignored | `policy` `src/generics.ts` `usesGeneric` |
| `imports` | imports, re-exports, `export default`, namespace imports | followed to the real declaration | `policy` `src/imports/main.ts` `imports` |
| `construct` | `new C()` | `Construct`; `init` is the constructor that runs: the class's own, else the nearest base class's **in project code**, up the chain. A chain that ends outside the project (`extends Error`) or at a base the checker cannot name has `init: None` and is **counted** (`inherited_constructor_external`, `inherited_constructor_unknown`; `Breakdown.notes`). An overloaded constructor's `init` is the implementation. A class outside the project is `External` (`new Map()`); a function reached by `new` is a `Call`; a class held by a value (`new Ctor()` with `Ctor: new () => X`) is `function_typed_value` | `fixtures/construct` `src/main.ts` `build` |
| `library-global` | a **library global called as a function** (`String(x)`, `Number(x)`, `Date()`) | `External`: the library declares it as an interface and a `var`, none with a body, and every declaration is outside the project (our choice among the engine's answers, `ENGINE.md`). Not `no_declaration` | `fixtures/construct` `src/main.ts` `convert` |
| `class-body` | property initializers and static blocks | belong to the **class** def's body | `policy` `src/class_body.ts` `Body` `makes` |
| `decorators` | decorators | a site in the body of the **class** that holds the decorated member (or of the decorated class itself), **parameter decorators too** (`constructor(@Inject(T) x)`, `method(@Body() b)`: they run when the class is defined). The decorated function is treated as if it had no decorator. `@dec` is one call. `@dec(1)` is **two**: the call of `dec` (a plain call site) and the call through its result, a site on the whole decorator expression: a `Call` when the checker's resolved signature names a function that can be entered (`return applyNamed;`), else `Unresolved(decorator_result)`, counted (an arrow written in the factory is already part of the factory's body; a function type such as `ClassDecorator` has nothing to enter) | `fixtures/site-kinds` `src/decorators.ts` `Decorated` |
| `jsx` | a **JSX element** `<Tag … />` | a site on the tag name (D8). A function or arrow component is a `Call`, a class component a `Construct` (`init` as for `new`), a value (`memo(...)`, `props.Icon`, `Ns.Icon`) is `function_typed_value`. An **intrinsic** tag (`<div>`, `<my-el>`: a lower-case first letter or a dash; `<svg:rect>`: a namespaced name) is **not a site**. A closing tag is not a second site | `fixtures/site-kinds` `src/jsx.tsx` `components` `intrinsic` |
| `tagged` | a **tagged template** `` tag`x ${f()}` `` | a site on the tag, resolved as a callee; a call in a substitution is a site of its own. A tag that is a call's result (``factory()`y` ``) is the existing `no_declaration`, as `f()()` is | `fixtures/site-kinds` `src/tagged.ts` `tagged` |
| `accessor` | an **accessor** `a.b`, `a["b"]` (a string literal key) where `b` is a getter or a setter | a site on the whole access, asked of the checker for every property access that is not a callee: the **getter** for a read, the **setter** for a write (`=`, a `for … of` target, a destructuring-assignment target), **both** for `+=`, `||=`, `++`, `--`. A union gives the accessor of every member that has one; a member that is a plain field runs nothing. A getter and a setter of a class of the project are two defs (`Box.value` twice, occurrences 0 and 1: two edges); of an external class one name: one edge. A property access that is **already a callee**, a tag, a decorator or a JSX tag is that site only, `delete a.b` and a computed key are no site. **A getter read by object destructuring** (`const { value } = box`) has no access to be a site: counted in `uncovered_destructured_accessor` | `fixtures/site-kinds` `src/accessors.ts` `reads` `writes` `compound` |
| `async` | `async` / `await`, generators | transparent; the body is walked | `policy` `src/async.ts` `run` |
| `callback-param` | a callback **parameter** being called (`function run(cb) { cb() }`) | `Unresolved`: the declaration is a parameter, not a function. This is the headline case for context sensitivity | `policy` `src/callback_param.ts` `runIt` |
| `function-typed` | any other **function-typed value** being called (a prop, a `setState`, a store action, a field of type `() => void`) | `Unresolved`, like the callback parameter: the engine answers with a `FunctionType`, which is a type and has no body. Counted in `Stats.language["function_typed_value"]` (the callback parameter too) (D16). **Only when the callee's symbol is declared as a holder of a value in the project** (a parameter, a property, a variable, a destructured binding, through an import alias too): that is what makes the count evidence. A callee that is not a name (`makeHandler()()`, `(a ? f : g)()`) is `no_declaration`. A value holder declared **outside** the project (`export declare const useQueryClient: () => QueryClient`) is a named `External`, not a D16 case | `policy` `src/function_typed.ts` `holders` |
| `object-arrows` | an **arrow held by a property** of a `const` object literal (`api.load()`, `tree.tasks.update()`, through `as const` / `satisfies`) | the arrow's def (D21), `Call`. A property that holds an arrow and is not a def (a `let`, `export default`, a class property's literal, an argument's literal, a `create(…)` result) is `function_typed_value`, as a callback is. A union receiver gives one target per member | `fixtures/object-arrows` `src/main.ts` `run` |
| `passed` | a **function named where a value is handed over** (D22) | a **passed edge** from the def that names it, at the name, to the def's context: the solver walks it, so what it calls is in the tree, and the node is drawn `[Passed]`. Each place a def is named is its own edge; a def both called and named in one body has both. A value that **holds defs** hands them over with it (D22 step 4): an object literal in a hand-over position hands over its function members at their keys, a name that holds a literal hands them over at the name, a named function expression in a hand-over position is handed over at its name. A literal that is only made, or that nothing hands over, hands nothing over; a class named as a value is not a function and is step 5's counter. A **destructuring initializer is a read** (`const { load } = api`, `({ load } = api)`): `api` hands nothing over, and a name it binds stands for the member it names (looked up on the initializer's type, through nested patterns and renames), so `use(load)` is the edge to `api.load` at `load`. A rest element, an array pattern, a parameter pattern and an assignment target are not followed | `fixtures/handed-over` `src/main.ts` `argMethodCalls` `calledElsewhereInTheTree` `destructureThenPass` |
| `script-global` | a **function in a script file** named like a library global (`fetch`, `open`, `close`, `name`) | the checker merges them into one symbol and lists both declarations; **D19**: when a declaration with a body is in project code and every other one is in a declaration file (a bundled library, a package's `.d.ts`), only the project's stay. Narrow on purpose: with no project body, or another project declaration, the engine's list is the answer (a project `declare function alert` keeps its `External`) | `fixtures/script-global` `main.ts` `caller` |
| `any` | a value of type `any` or an untyped JavaScript value | `Unresolved` | `policy` `src/any.js` `untyped` |
| `computed` | `obj[name]()` with a computed name | `Unresolved` (`computed_name`) unless the checker narrows the name to a literal, in which case it is resolved (`counter["bump"]()`: through the checker's signature, not the call hierarchy, which finds nothing for an element access) | `policy` `src/computed.ts` `byName` |
| `project-code` | project code | not under `node_modules`, not a `.d.ts`, not a bundled lib. A call that resolves into the **repo's own** `.d.ts` is `External`, not a def (TS3 pinned that such a file is absent from `files()`; this is the half that needs call resolution) | `policy` `src/external/main.ts` `external` |
| `external-call` | an external call | an `External` edge with the package name; never entered | `policy` `src/external/main.ts` `external` |
| `dts-shadow` | a `.d.ts` beside its `.js` in the project | the `.d.ts` wins in the checker; the target is `External`. **[check]** with S-TS3 whether this is common in your target projects | `policy` `src/dts_shadow/main.ts` `viaShadow` |
| `uncovered-hand-over` | what no edge covers: a hand-over by element access, `bind`, a class named as a value, a call through `call`/`apply` (D22 step 5) | Counted, never drawn: `Stats.language["uncovered_element_access"]`, `_bind`, `_class`, `_call_apply`, per occurrence in every walked body. No edge, no node. A computed key and a spread of an object that holds defs are not counted (they cannot be told from code that is not a def). See `ENGINE.md` ("What no edge covers") | `fixtures/handed-over` `src/main.ts` `elementAccessHandedOver` `bindHandedOver` `classHandedOver` `callAndApply` |
| `counter-rest` | a **rest element** that takes over function members | `const { load, ...others } = api; use(others)`: counted in `uncovered_rest_element`, one for each place the rest name is handed over, when the rest object holds a project function with a body. A rest object that is called (`others.save()`), unused or without a def reads 0. **A rest in an assignment pattern** (`({ ...o } = api); use(o)`) and **in a `for … of` pattern** count here too. No edge: a rest element is not one member | `fixtures/uncovered` `src/members.ts` `restTakesFunctions` `restIsCalled` `assignedRestHanded` `assignedRestNotHanded` |
| `counter-assign` | an **assignment destructuring** that takes a function member | `({ load } = api); use(load)`: counted in `uncovered_assignment_destructuring`, one for each place the assigned variable is handed over, when the member the target takes is a project function (renamed targets and nested patterns too). A target that is called, never used or not a def reads 0; so does a `==` with an object on its left. No edge: the variable has no initializer to read | `fixtures/uncovered` `src/members.ts` `assignedAndHanded` `assignedAndCalled` |
| `counter-initializers` | class-body sites that a **construction** does not draw | `new C()`, `<C />` and `super()` draw the constructor (`init`), not the instance field initializers. Counted in `uncovered_construct_initializer_sites`, one for each **site** in an instance field initializer of the class and of every class the construction goes through without a constructor to enter. A field that holds an arrow or a function expression is its own def, so its calls are not class-body sites (0); static initializers and static blocks run when the class is defined (0); a parameter property's default is a site of the constructor (drawn). The owner's decision: a design note first (`docs/02-tree-rules/07-what-a-construction-runs.md`), no edge yet | `fixtures/uncovered` `src/classes.tsx` `constructsWithField` `constructsStaticOnly` `constructsDerivedNoConstructor` |
| `counter-local-decorators` | the decorators of a class **declared inside a function** | Counted in `uncovered_local_class_decorator_sites`, one for each site in a decorator (the class's, a member's, a parameter's; `@factory(1)` is two) of a class declared inside a walked body. The decorators run when the body does, and the body stops at a nested class. A class at the top of a file reads 0. Decorators stay sites of the class body (owner's decision) | `fixtures/uncovered` `src/classes.tsx` `declaresDecorated` `declaresPlain` |
| `counter-render` | a **class component**: `<Cls />` and its `render` | `<Cls />` draws the constructor. Counted in `uncovered_class_component_render`, one for each element whose class has a `render` that is a project function (its own, inherited from a project class, or an arrow held by a field). React calls `render` and the analyzer holds no framework rule (owner's decision), so it is not drawn. A function component and a `render` declared by a package read 0 | `fixtures/uncovered` `src/classes.tsx` `showsWidget` `showsFunctionComponent` |
| `counter-getter` | a call through a **getter's result** | `b.fn()` where `fn` is a getter: one call edge, to the getter (the engine's answer); the call of what it returns is counted in `uncovered_getter_result_calls`, never a second edge on the same span. A method and a plain read of a getter (an accessor site) read 0 | `fixtures/uncovered` `src/getters.ts` `callsResult` `callsMethod` |
| `counter-for-of` | a **`for … of` destructuring** that takes a function member | `for (const { load } of xs) use(load)`: counted in `uncovered_for_of_destructuring`, one for each place the name is handed over, when the member it stands for (looked up on the type of the pattern, through renames and nested patterns) is a project function. A `for … of` pattern has no initializer to read, so no edge follows it. A name that is called, never used or not a def reads 0; an array pattern is not followed | `fixtures/uncovered` `src/members.ts` `forOfHanded` `forOfCalled` |
| `counter-computed-names` | the **computed member names** of a class at the top of a file | `class Top { [key()] = 1 }`: counted in `uncovered_computed_member_name_sites`, one for each site in a computed name, where the class def is walked (as the entry). A class def's body never reads its member names; a class **declared in a function** has them read by that function (an edge there, 0 here). A construction does not walk the class, so it counts nothing. Definition-time sites get a counter, not an entry (owner, 2026-11-12; D25) | `fixtures/uncovered` `src/classes.tsx` `ComputedTop` `ComputedNoSite` |
