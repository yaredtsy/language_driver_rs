## TC2 step 2 as built: `Expr::Param` and the parameter table (`4bb4e98`; reviewed 2026-11-24)

**What it is.** `Expr::Param(i)`: an identifier whose symbol's `value_declaration` is one of the def's own parameter nodes (the syntax list
without a `this` parameter, kept in the reader), asked before `functions_named`. `Param { rest, named, default, assigned, capable }`
(`06-tc2` §2): `default` is `expr_of` of the initializer in the def's own table; `capable` is `!holds_only_data(get_type_of_symbol(..), 4)`
(a union whose members all are; `TypeFlags::Primitive | Never`; an array whose element is; a tuple is not looked into); `assigned` is TC0's
`names_in` / `writes_of` (back from `25793b3`, where they were in `sem/resolve.rs`) on a named, capable parameter. `eval` answers unknown for
`Param` until step 3, so no graph moves. The four new fields carry no `expect(dead_code)`: `Param` derives `PartialEq`, which reads them.

**Engine items `sem/flow.rs` now calls** (the reviewer checked the three checker methods at the pin `13a31a4`): `Checker::get_type_of_symbol`
(`checker_08.rs`), `Checker::is_array_type` (`checker_11.rs`; covers `ReadonlyArray`), `Checker::get_element_type_of_array_type_exported`
(`services.rs`; `get_type_arguments(t)[0]` only after its own `is_array_type`), `Symbol::value_declaration`, `Type::flags` and `Type::types`
(on a union only), `astnav::get_touching_property_name`, `tsrs_core::index_bytes`, `tsrs_scanner::is_identifier_part`.
`TypeFlags::Primitive` (`types.rs`) is `StringLike | NumberLike | BigIntLike | BooleanLike | EnumLike | ESSymbolLike | VoidLike | Null`:
template literals are in `StringLike`, `Enum` in `NumberLike`, `Undefined` in `VoidLike`. **Not used, on purpose:** `get_type_arguments`, which
downcasts with an assert (`t.as_type_reference()`), so a tuple is capable. **A declaration's own name is a `Read`** for `ast::is_write_access`
(`access_kind`: a `Parameter` parent falls to `Read`, read at the pin), so TC0's filter of it was dead and is gone.

## TC2 step 3 as built: values for functions, anonymous functions and `Undefined`; `eval` answers (`36434b3`; reviewed 2026-11-24)

**What it is.** `One::{Fn, Anon(DefId, u32), Undefined}` in that order; `Value::contains` (a binary search: members are sorted) and
`Value::without` (through `of_capped`, so the normal form is made in one place). `Env { flow, def, key: KeyData }`, filled by `Lang::walk`
through `Keys::data`. `eval` answers `Data`, `Def`, `Anon`, `OneOf` (the join) and `Param` (the key's slot, unknown when the key does not
list it, since a key drops trailing unknowns; unknown for a rest parameter; a default where the slot holds `Undefined` or is open; joined
with unknown when assigned), and a default sees only the parameters before its own (`eval_below`). `resolve_from_env` evaluates the callee
and still answers `None`: no graph moves. No engine item is new. `Flow::params` lost its `expect(dead_code)` (read by `eval`); still
expected dead outside tests: `Flow::anons`, `Flow::handed`, `SiteFlow::{span, kind, args, anon}`.

**Reviewer:** 422 passed, 12 ignored; clippy clean. Mutations: the coder's five ((a) no open-key half of the default rule, (b) the default
seeing every parameter, which overflows the stack on `a = a`, (c) no `assigned` join, (d) `without` keeping the member, each caught; (e) the
key in `Env` from `KeyData::default()`, caught by nothing, as expected: every key is the open one until step 4, whose proof must reach it);
the reviewer's one more: `<` → `<=` for a default's bound, caught (stack overflow on `a = a`). With the layer on, depth-1 graphs of V-NOC,
the private codebase and the compiler hash as at `137b4fa`, no panic.
