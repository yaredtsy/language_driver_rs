## TC1 step 1 as built: the switch and the interned key (`c2452bb`; reviewed 2026-11-24)

**What it is.** `Precision::{Default, Precise}` (public, `#[non_exhaustive]`, in `calls.rs`), `Options::precision` (`Default` from
`Options::new`), `typescript-cli calls … --precise`. Nothing reads the switch until step 4. `type Key = KeyId`: a `u32` into the request's
`Keys` (`key.rs`, an `indexmap::IndexSet<KeyData>` and a `Vec` of digests at the same places), held by `TypeScript` in a `RefCell` and read
by `Lang::digest`. `KeyData` has no field, so `KeyId::OPEN` (0, digest zeros) is the only key. The six `()` keys of the crate (four in
`walk.rs`, two in `calls.rs`) are `KeyId::OPEN`, or the type `Key`; there was no seventh.

**No engine item is called.** The dependency: `indexmap = "2"`, which tsrs already takes at 2.14.2 with its default features. `Cargo.lock`
gains one line (`"indexmap"` in `typescript-analysis`'s list) and no `tsrs_*` crate is compiled again (coder's report; the lockfile diff
read by the reviewer).

**Reviewer:** 387 pass, 11 ignored (383 + 2 key tests + 2 in `typescript-cli/tests/precise.rs`, which runs six scenarios × four outputs with
and without `--precise`). clippy clean on both crates. Two mutations, both caught: `digest_of` answering ones fails the key test and
`budget.rs`'s no-flag snapshot (the `--graph` output prints the digest); `intern` not pushing a new key's digest fails both key tests.
Depth-1 dumps (`TS_SWEEP_FILE_CODE=1`, dev profile) are equal, graph for graph, to `fbee1b4`'s: V-NOC 1,871, the private codebase
15,575, the TypeScript compiler 12,136. `TaskDetailPanel`'s merged wire and breakdown are byte for byte the same with `--precise`.

## TC1 step 2 as built: a body as plain data, and the gate (`bac93f9`; reviewed 2026-11-24)

**What it is.** `flow.rs` (no engine import): `DefId { program, file, def }`, `Flow { params, sites, anons, unhandled }`, `SiteFlow`,
`Arg`, `AnonFlow`, `Expr::{Unknown, Data, Def, Anon, OneOf}`. `sem/flow.rs`: `Flows` (the program's number from a global counter, the
files as an `IndexSet<P<SourceFile>>`, the memo by `DefId`), `Sem::def_id`, `Sem::func`, `Sem::flow`, and a private `Reader` that reads one
body with one checker handle inside `view::counted`. `Collector` and `Body` list the anonymous functions. Nothing calls `flow` outside
tests yet; the three places that hold it carry `cfg_attr(not(test), allow(dead_code))` until step 4.

**Engine items.** No new engine function. Read through views: `FunctionLike::parameters` (`Node::parameters`, on FunctionDeclaration,
FunctionExpression, ArrowFunction, MethodDeclaration, GetAccessor, SetAccessor, Constructor), `Parameter::is_rest`
(`as_parameter_declaration().dot_dot_dot_token()`), `Conditional::when_true` / `when_false` (the public fields of
`as_conditional_expression()`). Free functions: `ast::is_this_parameter`. The checker, through the existing `functions_named`.

**A hole H17 missed, closed.** `Node::parameter_list` is `self.function_like_data().unwrap()`, and `Node::parameters` calls it: a node that
is not function-like panics. It was not in the ban, which listed the accessors that end in `panic!`. A scan of every `pub fn` of `impl
Node` in `tsrs_ast/src/ast.rs` at the pin for `unwrap`, `expect`, `panic!` or `unreachable!` found 30: 24 already banned, `parameter_list`, and
five that do not depend on a node's kind or that `sem` never calls (`set_flow_node`, `eager_jsdoc`, `as_node`, `original_text`,
`set_jsdoc_cache`). Both are banned now (`clippy.toml`); `collect.rs`'s two calls go through `parameters_of`. An engine bump re-runs the
scan (the command is the one above the downcast list, with `ast.rs` and these words).

**Spellings.** Every `Kind` name of `to_expr`'s data rule is the engine's as the plan wrote it (`PlusToken` … `CaretEqualsToken`,
`InstanceOfKeyword`, `InKeyword`). The private function is `expr_of` (clippy's `wrong_self_convention` refuses a `to_*` taking `&mut self`).

**Reviewer.** 392 pass, 12 ignored; the totality walk meets every kind of the two new views (197,638 nodes, 39 fixture projects); the
table equals `call_sites` on all 865 defs (772 sites) of the fixtures. Mutations: dropping the program check fails the program test;
keeping the `this` parameter fails the parameters test; taking the outermost anonymous function instead of the innermost failed nothing
(no fixture had one inside another): fixed by `4ce3540` (`run(() => run(() => target(3)))`), and that mutation now fails test 1 (reviewer's run). Depth-1 dumps equal to `c2452bb`'s on the three projects.

## TC1 step 3 as built: the hand-overs in the table (`6b7c2ef`; reviewed 2026-11-24)

`Flow::handed: Box<[HandedFlow { at, value, written }]>`: every `Handed` of `Sem::handed_over` as `Def`, then every name of `Body::refs`
at a span no `Handed` has, through `expr_of`; stable-sorted by place. `handed_over` is called in `Sem::flow` before the table takes the
checker. No engine item is new.

**What it found.** `expr_of` and `handed_over` never disagree: on the 179 hand-overs of the fixtures and on every def of the three
projects, the `Def`s of the table are exactly `handed_over`'s, and no name `handed_over` found nothing for resolves to a def through
`expr_of`. In `flow` (the fixture) the three names with no def are `p`, `Shape` and `q`; the operands `p` of `p || held` and the others are
not in a hand-over position (`is_handed_over`), so they are not listed.

| Project | Hand-overs in the tables | of them defs (D22's) |
|---|---|---|
| V-NOC frontend | 6,188 | 153 |
| the private codebase | 89,263 | 1,906 |
| TypeScript 5.9.3 `src/compiler` | 81,903 | 5,545 |

So 97% (V-NOC) to 93% (the compiler) of the names a body hands over are not a def today: they are what TC2 (a parameter) and TC3 (a
local) are for.

**Reviewer.** 393 pass, 12 ignored. Mutation: listing every name, also those `handed_over` has, fails test 6 and test 4. Depth-1 dumps
equal to `c2452bb`'s on the three projects. **The gate again** (release, `/usr/bin/time -l`), with `handed_over` now inside `flow`:

| Project | Depth-1 graph | Tables, cold | after the graph | Peak: graph / graph + tables / tables alone |

`value.rs` (no `sem` import): `Value` is a struct around a private `Repr` (`Set { known: SmallVec<[One; 2]>, open }` or `Wide`), built only
by `unknown`, `data`, `wide`, `of`; read by `known`, `is_open`, `is_wide`; `join`. `One::Fn(DefId)` alone, `MAX_SET` 8. `KeyData::params`,
with `normal` dropping trailing unknowns; `digest_of` asserts (debug) it is given the open key. `DefId` derives `Ord`. No engine item.

**Dependency.** `smallvec = { version = "1.16", features = ["union"] }`, as tsrs builds it: `Cargo.lock` gains one line (`"smallvec"` in

**The laws, exhaustively** (no `proptest`, 05-tc1 §8): 53 values (every subset of five functions of at most three, open and closed, and
`wide`), 2,809 pairs and 148,877 triples: commutative, associative, idempotent; `wide` absorbs; `data` changes nothing; `unknown` opens and
keeps the members; a join is wide exactly when a side is or the union passes the cap. All held on the first run.

## TC1 step 4b as built: the layer runs, and knows nothing (`9530a7d`; reviewed 2026-11-24)

**What it is.** `caps.rs`: `Caps` (`bitflags`, six bits, one per phase), `Caps::BUILT` empty. `Precision::layer()`: `Default` is `None`,
`Precise` is `Some(Caps::BUILT)`, and an empty set is a layer that runs. `TypeScript::with_layer`, set by `graph_within` from the options.
`Lang::walk`, layer on: `World::flow(self, sem.def_id(f))` into `Env { flow }`, `flow.unhandled` noted; layer off: no `def_id`, no
`flow`. `walk::body` / `body_of` / `resolve` take `Option<&Env>`; `resolve_from_env(lang, env, site_index)` evaluates the site's callee and
returns `None`. `eval.rs`: the `World` trait (`flow` only), `eval` with one arm per `Expr`, all `Value::unknown()`. `Sem::flow` now counts
what `handed_over` meets inside the table's count. The four module/field `allow(dead_code)` are gone. The items TC2 reads first carry
`cfg_attr(not(test), expect(dead_code, reason = "read from TC2 on"))`:
`flow.rs` `Flow::params`, `anons`, `handed`, `SiteFlow::span`, `kind`, `args`, `anon`; `value.rs` `MAX_SET`, `One::Fn`, `Repr::Wide`,
`Value::data`, `wide`, `of`, `is_open`, `is_wide`, `join`, `of_capped`, `join_capped`. `sem/flow.rs` and `Sem::flows` needed none.
`tests/sweep.rs` reads `TS_SWEEP_PRECISE=1` and prints `precision: …`.

**No engine item is called.** The dependency: `bitflags = "2"`, which tsrs takes at 2.13.2 with its default features: `Cargo.lock` gains one
line (`"bitflags"` in `typescript-analysis`'s list), no crate of tsrs is compiled again. An unused flag of a `bitflags` struct gives no
`dead_code` warning (probed with 2.13.2 before the step).

**The proof.** `tests/precise.rs`: 368 cases (every case of `common::cases()`, and every def and file entry of `flow`, `handed-over`,
`site-kinds`, `object-arrows`, `anonymous-in-place`), each `Default`, `Precise`, `Precise` again on one `Project`: all equal, stats included.

**Reviewer.** 405 pass, 12 ignored. Three mutations, each caught: `with_layer` dropping the set fails `the_layer_reads_a_table_only_when_it_is_on`
(and nothing else: the graph equality alone could not see it, which is why that test exists); `eval` answering `data` for `Data` fails
`every_expression_is_unknown_in_tc1`; `resolve_from_env` answering `Some(vec![])` makes 197 of the 368 cases differ. Depth-1 dumps
(`TS_SWEEP_FILE_CODE=1`, dev profile), **with the switch off and with it on**, equal to `137b4fa`'s graph for graph: V-NOC 1,871

tables kept). Resident memory is not the gate's peak footprint: step 6 measures both in the release build.
