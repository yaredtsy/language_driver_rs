## TC4 step 1 as built: the table reads objects, members, patterns and JSX attributes (`9e64de5`; reviewed 2026-11-26)

**What it is.** As decided (08-tc4 §10, "Step 1"): `Expr::{Member, Object, Omit, Default}`, `Part::{Named, Spread, Unnamed}`;
in `sem/flow.rs` `Initial::{Node, Element}`, `Reader::{element_value, element_key, property_name, declaration_is_open, symbol_of,
member_of_access, part_of, jsx_attributes}` and the free `is_open_by_form`, `member`, `omit` (the only makers of their variants). Every
reader gives the new variants `Unknown`'s reading (`eval_below`, `relevance` `Marks::atoms`, `walk::holds_name`,
`walk::reads_many_sources`); `needs::each_expr` is a `match` with no `_` arm. The method of a literal is `literals.<locals>.short.m`.

**Three choices the coder made, accepted:**
- **A shorthand `{ f }`** is read through the shorthand node and `get_shorthand_assignment_value_symbol` (`Reader::symbol_of`): the node's
  own symbol is the property, so the name node alone would read `?`. `functions_named` and `handed.rs` already did the same.
- **A def read through a member is not a hand-over**: the test helper `holds_a_def` does not enter `Member` or `Omit`
  (`register(handler.length)` reads `member(def handler, length)`, a property of the function, not the function), only `Default` and an
  object's parts.
- **A rest parameter's pattern** (`...{ length }: unknown[]`) stays open: `Param(i)` there is the list, not one value. No fixture line yet
  (step 2 adds one).

**Changed table lines**: the tour (6): `open`'s and `emit`'s callees `member(param#0, onDone)` / `member(param#0, write)`; `Panel`'s
`onClose@13 capable = member(param#0, onClose)` (no longer `open`); `call def open ({onDone: def encode})` and
`jsx def Panel ({onClose: def join})`, twice each. `vars.flow.txt` (1): `call member(var FILE:items@4, forEach) (anon#0)`. Two hand-written
expectations of `the_table_of_flow_reads_each_callee_and_argument` moved as intended (`{held: def held}`, `jsx def Card ({title: data})`).
The new `objects.flow.txt` matches the prompt's expectations line by line (`members` has five sites: `getThing()` is one).

**Reviewer's checks.** 502 passed, 13 ignored; only the three table snapshots moved; static checks pass. The coder's mutation (no normal
form for `member`) fails the objects and tour tables and `a_name_of_a_parameter_is_its_place`.

**For step 2.** `jsx_attributes` counts any child node, whitespace-only text included, so `<P>\n</P>` has `children: ?`; JSX drops a
whitespace-only line, so step 2 should not count it (`JsxText` that holds only trivia), since from step 2 a complete object without
`children` reads `Undefined` there.

## TC4 step 2 as built: values for objects, off (`e698cfe`; reviewed 2026-11-26)

**What it is.** As decided (08-tc4 §10, "Step 2"): `captures.rs` is `nested.rs` (`Nested`, `MAX_DEPTH` 2, `MAX_MEMBERS` 64,
`VALUE_WIDENED_DEPTH`, `VALUE_WIDENED_MEMBERS`, `ObjectData`, `intern_object`, `object`; both interns share `normal_value` and
`depth_of_one`); `value::ObjectId`, `One::Object` last, `Value::opened_without`; `eval`'s `defaulted` (shared with `passed`),
`made_object`, `object_literal`, `member`, all behind `Caps::OBJECTS`, which is not in `Caps::BUILT`; `Canon::Object` last,
`Names::objects`, `Keys::intern(…, objects)`; `World::{object, object_data}` (the quiet wrapper passes both through; the test worlds of
`needs`, `relevance` and the table tests answer `(None, 0)` and `unreachable!()`). `walk.rs` got two arms for `One::Object`
(`member_order` sorts it last; a call on an object leaves the site open, an object is not callable). Pinned digest of a key holding
`{onDone: save}` (complete): `OBJECT` in `key.rs`, every older pin unchanged.

**Read against the design.** The depth cut works bottom-up, as `normal_value` interns: in `{x: {y: {z: f}}}` the depth-2 object is
removed from `x`'s value (unknown, one cut), not the innermost from `y` (the prompt's wording was wrong; the plan's rule, "an inner object
too deep is removed from its value, which becomes open", is what was built). A capture list drops an entry the cut leaves unknown (a list
lists no unknown entry); an object keeps it.

**Reviewer's checks.** 521 passed, 13 ignored (502 + 19 unit tests); no file under `tests/` moved. The prompt the coder received was
cut off before its mutations; the coder ran three of its own (the bit ignored, a missing member read as unknown, the digest by number:
each caught). Mine, the prompt's (b), an object's stored depth counted without its inner closures: **not caught** (174 lib tests green).
The stored depth matters when the object is put in a list or another object; step 2b adds the test.

**Step 2b** (`9ef8b5f`; reviewed 2026-11-26): the two tests, no code change. `an_objects_depth_counts_its_closures` fails under mutation (b)
(`left: 1, right: 2`), and only it: nothing else covered an object's stored depth. `a_variable_that_holds_an_object_settles`: `x = f; x = g`,
`y = {a: x}` settles in **3 rounds**, and `y` holds **two objects**: round 1 read `x` before it settled and made `{a: data}`, round 2 made
`{a: {f, g}}`, and the round join keeps both. `member(y, a)` is `{f, g}`: sound. 523 passed, 13 ignored.

**What the two objects mean.** An object is interned by its members, so a variable whose object is built from a variable that settles over
rounds keeps one object per round. Every answer through it is right (an earlier round's object holds less), but a key holding it has a
different digest from a key holding the settled object alone, so equal values can split a context. 08-tc4 §10 row 10 says what is done.

## TC4 step 3a as built: the table records the uses (`874d096`; reviewed 2026-11-26)

**What it is.** As decided (08-tc4 §10, "Step 3", 3a): `flow::Uses { escapes, passed, names, receiver, exported }` on `Var` (capable
rows) and on `Param` (a pattern parameter's `names`); in `sem/flow.rs` `referenced_identifiers` (one walk of the whole node, nested defs
included; only identifiers whose name matches a capable row's are asked of the checker, a cost filter with no effect on output),
`Reader::{place, uses_of, is_exported, pattern_vars, pass_to}`, a private builder `Found`, and `wrapped`, `is_tested`,
`is_in_type_query`, `sorted`; a `PrefixUnary` view in `sem/view` (the `!` operator's accessor is banned outside it). Exports:
`get_combined_modifier_flags` with `ModifierFlags::Export` first, then the module symbol (`get_symbol_of_declaration_exported` on the
file) and `get_exports_of_module_exported`, each alias through `get_aliased_symbol`.

**The coder's choices, accepted:** a second name with no row (declared in a nested def) escapes; `new x.C()` is not a receiver (`this`
in a constructor is the new object); a reference in a type query (`typeof x` in a type) is not a use; point 4 is not recursive
(`a && b && x` leaves `x` escaping: toward untrusted); a `for` tests all three of its expressions. Checked by the coder with a removed
fixture: a shorthand `{ loc }` escapes; `export { x }` and `export default x` are `exported`.

**Reviewer's checks.** 524 passed, 13 ignored; only the table snapshots moved (`trust.flow.txt` new; 27 rows and 3 pattern parameters
gain their uses in the others); every expected line of `trust.tsx` matched before blessing. Both mutations are caught (and each also
fails one older table).

**Found in review: a hole in the rule, not in the code.** Point 1 allows any read chain, so `const b = x.b; b.c = f` leaves `x` trusted
and `x.b.c()` would be answered from a key the code changed. Fixed in the plan (3a-fix): a chain whose top can hold a function or an
object is placed again as if it were the reference. Also written: a pattern parameter's own elements are never opened in its body (read
at the entry), so a component that destructures its props keeps them whatever else it does with them.
