## Before TC4, step 0a as built: the cap on contexts per function (`c6b88b2`, `7021f7a`; reviewed 2026-11-26)

**What it is.** As decided (08-tc4 §0): core's `Limits::max_contexts_per_function: Option<u32>` (`None` by default and in `Limits::new`) and
`Cut::MaxContextsPerFunction` (`"max_contexts_per_function"`, after `MaxContexts`). `graph_within` counts per function the contexts it reads
(`Run::per_function`, raised right after `read += 1`); the checks run `max_contexts`, `max_depth`, the cap, the cancel. TypeScript:
`calls::CONTEXTS_PER_FUNCTION = 64` and `calls::limits()`, used by `Options::new` and by the measure's `solve_timed`; the tests' own
`Limits::default()` and `Limits::new(u32::MAX, None)` are unchanged.

**Tests.** Core, on a toy language with keys (`Fan`: `main` calls `f` under 1, 2, 3; `f` calls `g`):
`max_contexts_per_function_cuts_the_next_context_of_that_function`, `max_contexts_per_function_none_or_one_context_never_cuts` (also `Toy`'s
diamond at cap 1), `max_contexts_per_function_counts_reads_so_a_warm_memo_cuts_the_same` (the second graph equals the first in entries, defs,
contexts, edges and cuts; `walks` 4 then 0). TypeScript: the row `cap-per-function` (three contexts of `run`, nothing cut) and
`the_cap_per_function_cuts_the_third_context_of_run` (cap 2: `run`'s third context, the one `third` calls, is `Incomplete`, counted once; no
call reaches `c`, which `third` still hands over as a passed edge; both properties hold; cap 3 = no cap). The four `*-off.txt` snapshots gained
the new row's section (+2 lines each: they are written over every row of the table; the prompt missed that).

**Reviewer's checks.** Tests: core 165 + 23, TypeScript 500 passed / 13 ignored, Rust 257 / 14, Bend 209 / 16, static checks pass; Python
not built (CI owes it, as for every core change). The coder's mutation (`>=` → `>`) fails the two cut tests in core and the TypeScript test.
Mine: count only walks (a memo hit not counted) fails `…_counts_reads_so_a_warm_memo_cuts_the_same`. The snapshot read against the fixture.

## Before TC4, step 0b as built: the allowance by site (`d581079`; reviewed 2026-11-26)

**What it is.** As decided (08-tc4 §0): `Spoken::emptied` (`members` saw `Undefined` and no target is left, the open-entry path of
`walk::resolve_from_env`); `resolve` returns `(targets, emptied)`; `body_of` calls `TypeScript::note_emptied(f, site)`;
`TypeScript::emptied_sites` names each def by `Sem::describe(..).id`, sorted and deduplicated. `calls::graph_and_emptied` is the request,
`graph_within` its graph. The feature `__testing` (`Cargo.toml`, commented as `__proof`) turns on `typescript_analysis::testing`
(`call_graph_and_emptied`, `session_graph_and_emptied`) and, only under it, `Session::options` (a plain build would warn it is unused); the
crate lists itself as a dev-dependency with the feature, which adds one line to `Cargo.lock`. `never_fewer_edges(default, precise, emptied)`:
(b) a lost site is allowed only when all its default edges were `Unresolved` and it is listed; (c) a listed site where the default graph
has an answer is reported. Callers pass the list of their precise graph: `graphs_of` (the rows), the cap test, `precise.rs`, the sweep's
`Comparison::entry`. New test `the_layer_lists_the_site_it_emptied` (`callback-not-passed`: `main` lists `run`'s `cb?.()` site, `run` and
`callback-either` `pick` list nothing).

**Reviewer's checks.** 501 passed, 13 ignored; no snapshot moved; `cargo build` sees no feature. The coder's mutations: not recording fails
the rows' property and the new test; dropping "is listed" fails the property's own test; recording every empty site (without
`saw_undefined`) changes no list on any row or shared case (an equivalent mutant today: on that path an empty result means every member
was `Undefined`; the condition stays as a guard). Mine, on the compiler's `createProgram` (whole graph, release sweep, compare mode):
**0 problems** with the list; with the list forced empty, **3 problems**: the precise graph loses 3 sites and the list names exactly those.
The old allowance would have let up to 92 (`callee_undefined`, per walk) pass. The sweep binary was rebuilt clean after the check.
