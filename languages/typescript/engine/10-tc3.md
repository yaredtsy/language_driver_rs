# TC3: variables and captures (the engine side)

What TC3 (`docs/03-typescript/12-context-layer/07-tc3-variables-and-captures.md`) found and measured, step by step.

## Before the design: V-NOC's open sites (reviewer, 2026-11-25, at `81485ce`)

TC2 answered none of V-NOC's 305 open sites (`09-tc2.md`, "TC2 step 9"). To see whether TC3 or a later phase is the answer, the sites
were listed with the sweep's own site measure (dev build, layer on: `TS_SWEEP_PRECISE=1 TS_SWEEP_SITES=<file>`, the handoff's
`sample-vnoc.txt`; no change to the code), and each callee's name was looked up in its file by a text script: where the name is declared,
and what its initializer is. The script reads text, not the program, so the buckets are close, not exact.

| Where the called function comes from | Sites | The phase that can answer |
|---|---|---|
| the result of a library hook: a zustand selector (`useProjectStore(s => s.x)`), `getState()`, `useCallback`, `useEffectEvent`, `useMemo`, `useRef` | ~154 | TC10 (a library function that returns its argument) for `useCallback` / `useEffectEvent`; a store's field is a library's value |
| a prop: a name of a destructured parameter (`function Dialog({ onClose }: Props)`) | 94 | TC4 |
| a project hook's result, taken apart (`const { refresh } = useConversations()`) | ~33 | TC4 and TC6 |
| a parameter of the function around (`createRafDispatcher(onFrames)` → its nested `flush` calls `onFrames`), or of a curried arrow | 9 | TC2 with TC3's captures |
| a local that is one of two values (`ReactIcon \|\| FallbackIcon`, `asChild ? Slot : "span"`) | 3 | TC3, but each holds a library component: no edge |
| another object's field (`tool.icon`, `face.ConfigForm`) and the rest | ~12 | TC4 / TC6 |

The counter's split (per context) was 172 from a call's result, 126 from a parameter, 29 from elsewhere: the 126 are mostly the 94
props, which the counter calls "from a parameter" because a destructured parameter is one.

**What it says.** The plan is not wrong: every bucket has a phase. TC3 answers at most about 10 of V-NOC's sites; its yield is in
imperative code (N4: 16% and 9% of the private codebase's and the compiler's capable locals are written more than once). For V-NOC the
phases that matter are TC4 (props) and TC10, which is not scheduled (D65: "later, with the counts of TC6").

## TC3 step 1: the variables of a body, read into the table (`5605717`; reviewed 2026-11-25)

**As built.** `Flow` has `vars` (one row per variable the def declares, sorted by `at`) and `unmodelled`; `Expr::Var(VarId)`, with
`VarId { def, at }`. The rows come from one walk of the def's own node that stops at a nested def (`Reader::declarations`); the writes
from one walk of the whole node (`written_identifiers`, which replaces TC2's `written_symbols` and now runs for every def), sorted by
place and given to the row of their symbol (`Reader::write`). A name becomes `Expr::Var` only where TC2 said `Unknown` (`Reader::var_of`),
and `eval` gives it the value unknown, so no graph moved: 452 passed, 13 ignored (449 + 3), and only `tour.flow.txt` changed among the
snapshots (each table gains its `vars:`; `Panel.<locals>.back` calls `var Panel:onClose@13`; `main` and `lineC` call `var h@…`, which holds
`def encode`: the tour's line c).

**Engine items called that were not before**, all already used elsewhere in the crate: `ast::get_combined_node_flags`
(`tsrs_ast/src/utilities_1.rs:1449`) with `NodeFlags::Ambient` (the context flag, so `declare const` and anything in a `.d.ts` are
ambient), `ast::get_source_file_of_node`, `Symbol::value_declaration`, `Node::name`, `Node::parent`.

**Two narrowings by the coder, accepted**: a `Parameter` has a row only when it is the def's own or its parent is an arrow or a function
expression (a parameter of a function type or a signature is not a variable, and the walk does not go into it); a `this` parameter never
has one.

**Found in review.**
- **Mutation c survived the first build** (the declaring def must be around the reader): its only real shape is a namespace merged from
  two blocks, whose second block reads the first's `export let h` by its bare name. A case was added to `vars.ts` (`N`, `N.use`:
  `call ? ()`); with it the mutation fails `the_variables_of_a_body_are_reviewed`.
- **A destructuring assignment with a default was read as a plain assignment**: in `[x = b] = arr` the written `x` is the left side of the
  binary `x = b`, which is itself a target of the outer assignment, so the row said `= def a; def b; def b` and not open, and `arr[0]` was
  lost (the reviewer's probe, reverted). From step 2 that would answer `x()` without the engine's open entry. Fixed in step 1b: such a
  write is open (`ast::is_assignment_target` on the binary).
- The `handed:` line `a def a` in the first `N` is TC2's: a name in a variable's initializer is handed over (as `encode` in the tour's
  `lineC`).
- The prompt's test count was the workspace's (449), not `-p typescript-analysis` alone (312): a reviewer's slip.
