## TC3 step 1: the variables of a body, read into the table (`5605717`; reviewed 2026-11-25)

**As built.** `Flow` has `vars` (one row per variable the def declares, sorted by `at`) and `unmodelled`; `Expr::Var(VarId)`, with
`VarId { def, at }`. The rows come from one walk of the def's own node that stops at a nested def (`Reader::declarations`); the writes
from one walk of the whole node (`written_identifiers`, which replaces TC2's `written_symbols` and now runs for every def), sorted by
place and given to the row of their symbol (`Reader::write`). A name becomes `Expr::Var` only where TC2 said `Unknown` (`Reader::var_of`),
and `eval` gives it the value unknown, so no graph moved: 452 passed, 13 ignored (449 + 3), and only `tour.flow.txt` changed among the
snapshots (each table gains its `vars:`; `Panel.<locals>.back` calls `var Panel:onClose@13`; `main` and `lineC` call `var h@…`, which holds
`def encode`: the tour's line c).

**Engine items called that were not before**, all already used elsewhere in the crate: `ast::get_combined_node_flags`
(`tsrs_ast/src/utilities_1.rs:1449`) with `NodeFlags::Ambient` (the context flag, so `declare const` and anything in a `.d.ts` are
ambient), `ast::get_source_file_of_node`, `Symbol::value_declaration`, `Node::name`, `Node::parent`.

**Two narrowings by the coder, accepted**: a `Parameter` has a row only when it is the def's own or its parent is an arrow or a function
expression (a parameter of a function type or a signature is not a variable, and the walk does not go into it); a `this` parameter never
has one.

**Found in review.**
- **Mutation c survived the first build** (the declaring def must be around the reader): its only real shape is a namespace merged from
  two blocks, whose second block reads the first's `export let h` by its bare name. A case was added to `vars.ts` (`N`, `N.use`:
  `call ? ()`); with it the mutation fails `the_variables_of_a_body_are_reviewed`.
- **A destructuring assignment with a default was read as a plain assignment**: in `[x = b] = arr` the written `x` is the left side of the
  binary `x = b`, which is itself a target of the outer assignment, so the row said `= def a; def b; def b` and not open, and `arr[0]` was
  lost (the reviewer's probe, reverted). From step 2 that would answer `x()` without the engine's open entry. Fixed in step 1b: such a
  write is open (`ast::is_assignment_target` on the binary).
- The `handed:` line `a def a` in the first `N` is TC2's: a name in a variable's initializer is handed over (as `encode` in the tour's
  `lineC`).
- The prompt's test count was the workspace's (449), not `-p typescript-analysis` alone (312): a reviewer's slip.

## TC3 step 1b (`7abcdcf`; reviewed 2026-11-25)

`Reader::write`: a write `x = e` (or `||=`, `??=`, `&&=`) is an assignment only when the binary is not itself an assignment target

`x@113 capable = def a; def b; def b` to `x@113 capable open = def a`; the mutation that undoes it fails `the_variables_of_a_body_are_reviewed`.

## TC3 step 2, part 1: the values of a body's variables (`a988bd6`; reviewed 2026-11-25)

**As built.** `eval::solve` gives every row of a body's table its value in one go, the first time the walk reads a variable (`Env::vars`, a
`OnceCell`): rows start as data (the empty value), rounds recompute every row from the last round's values until nothing changes (at most
32, then every row is opened and `variable_rounds_capped` counted), and a last round with the real world gives the answer, so
`value_widened_set` is counted once. A written parameter is its row (the slot joined with what the body assigns). `Caps::BUILT` is
`PARAMS | LOCALS`. Inside `eval.rs` the world is a `&dyn World` (a reference with a table of the trait's methods): with a generic, `solve`'s
`Quiet` wrapper made the compiler build `Quiet<Quiet<…>>` without end. 461 passed, 13 ignored.

**Proofs read.** `locals-off.txt` (every entry's graph with `PARAMS` alone, 70 entries) was written before the code changed and is unchanged
after: with `LOCALS` off the layer is TC2. The moved "on" halves are the rows' text: `local-alias` (`run @3fa907f4` draws `handler`, the
same context as `callback-reassigned`'s), `local-open` and `local-write-unmodelled` (`a` beside the engine's unresolved edge),
`local-cycle` (`a`, complete), `local-data` (`main` and `literal` share `run @6eee0fda`, the key of data), `callback-reassigned`
(`handler` and `fallback`, complete; at `run` itself `fallback` and unresolved), the tour's line c (`encode`). `local-either` and
`local-assigned-twice` wait for part 2. The coder's five mutations are each caught; the reviewer's (`Quiet` says it does not know
`LOCALS`, so the quiet rounds read no variable) fails three of the evaluator's tests.

**Found in review.** The brief did not name `the_counters_follow_the_edges` (`tests/context.rs`), which pinned `callback-reassigned`'s
open entry; the coder updated it, rightly (the lesson of handoff 08: name every test that pins the behaviour a step changes). A one-round
`solve` passes the small fixtures, because the last counted round acts as a second one: only the chain tests catch it.

## TC3 step 2, part 2: add beside the engine (D59), and the ceiling of 2b (`b4e28bd`; reviewed 2026-11-25)

**As built.** `walk::members` is the one place a value's members become targets (the tripwire, the arrow mark, `Undefined` reported, a
function the engine already calls skipped before the tripwire is asked); both ways of speaking use it. The new way: where the engine's
answer has no open entry, `LOCALS` is on and the callee holds an `Expr::Var` or an `Expr::Param` (`holds_name`), the layer keeps all the
engine's targets and adds the value's other functions, counting `variable_added_to_engine`; it notes nothing unless it adds. The coder's
mutation d (no name condition) found `run(cb: typeof a)` called with `b`: the engine names `a`, the key holds `b`, so the rule was widened
from `Var` to `Var` or `Param` (`62c0c9e`, row `callback-named-by-type`). The walk-alone test now runs with `Caps::BUILT` (it ran with
`PARAMS` only, so a duplicate target of this step was invisible to it). 461 passed, 13 ignored; the context table has 71 entries;
`locals-off.txt` only gained the new row's two entries.

**Not fixed, small**: a variable holding an arrow at a site the engine already marks `anonymous_function_called` adds the same mark again;
`Graph::new` drops the equal edge, but `variable_added_to_engine` counts the site. For the next step's prompt.

counts, the distinct ones where a read with two or more sources **holds a function** (anything else, data or unknown, cannot change an

|---|---|---|

The private sample's callee sites, read by hand (22 by file and place; 23 by def and place, one site counted under two defs): 18 are the
React compiler's memo cache (`if ($[k] !== x) { T0 = C; $[k] = T0; } else { T0 = $[k]; }`, then `<T0 />`), where both assignments reach
the call (the two branches of an `if`); 4 are a callback declared `null` and later set to a function (2 of them also set back to `null`),
read in nested functions too: the `null` source is data and draws no edge, so reading it in order changes no edge either. In every one
the order of the code gives the same edges as the join. The compiler's sites are
all arguments (the checker's reassigned parameters, `source = …`, passed on): there the order could only shrink a key (fewer members, maybe
fewer contexts), never add or remove an edge at the site itself.

**What it says for 2b** (D67: built only if it pays): on these samples the order of the code changes no edge at a callee, and at most the
keys of about a hundred compiler argument sites. The decision is the owner's.

## TC3 step 3: captures (part 1 `fbb4080`, part 2 `8710c09`, cost fixes `a6a5549`, `51426df`; reviewed 2026-11-25)

**Part 1** (`Flow::around`, `needs.rs`): as designed; 466 passed. **Part 2** (`One::Closure`, `CaptureSets` with the depth cut at 2,
`KeyData::captured`, `Canon::Closure`, hand-overs keyed): every moved "on" half is its row's text (`capture-handler`'s `finish` calls `save`,
`capture-sibling`'s `second` gets `report` from `first`'s key, `capture-two-levels`, `capture-through-parameter` (the closure through three
keys lands in the **same** context as the hand-over), `capture-written-in-nested` (`a` and `b`), `capture-anonymous`, `capture-self` ends);
`captures-off.txt` byte-identical; every existing pinned digest unchanged; two new pins (a key with a captured entry, a slot holding a
closure). Contexts share a digest when their keys hold the same (`first` and `second` both `@227833d6`): a digest is the key's content.
`value_widened_depth` is 8 on `capture-self` (once per cut made while evaluating). **The coder found** that the depth cut is not monotone
(`capture-self`'s rounds swapped between two values for ever) and made `solve` join each round with the one before: accepted (sound,
`07-tc3` §4). The reviewer's mutation (the last round without that join) fails two tests.

**The cost bug, and its two fixes.** Part 2 made the compiler's sample take 19 s of graphs in a dev build (1.8 s at step 2), and a release
depth-1 round did not end in minutes (the owner noticed). A `sample` profile put the time in `needs`: (1) the memo lived in `TypeScript`,
made per request, so every request reaching a nested def of `createTypeChecker` (about 2,400 nested defs that name each other) re-solved its
component; fix 1 (`a6a5549`) keeps the memo with the program (`Sem`), solves with a worklist, and builds a closure's list from the sparse
sides; still 7.31x, because (2) a def outside the components solved so far started a new one and walked the same defs again (319 components
of up to 2,420 defs; the coder's first total, 1.33 s, was a running total printed at each new maximum and missed the rest). Fix 2
(`51426df`): a def already solved enters a component as a fixed node and is not expanded, so each nested def is solved once per program
(3,419 calls, 6,276 defs expanded, 0.58 s in all on the compiler). Neither fix changed a snapshot, digest or count.
