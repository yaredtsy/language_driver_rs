# TC3: variables and captures (the engine side)

What TC3 (`docs/03-typescript/12-context-layer/07-tc3-variables-and-captures.md`) found and measured, step by step.

## Before the design: V-NOC's open sites (reviewer, 2026-11-25, at `81485ce`)

TC2 answered none of V-NOC's 305 open sites (`09-tc2.md`, "TC2 step 9"). To see whether TC3 or a later phase is the answer, the sites
were listed with the sweep's own site measure (dev build, layer on: `TS_SWEEP_PRECISE=1 TS_SWEEP_SITES=<file>`, the handoff's
`sample-vnoc.txt`; no change to the code), and each callee's name was looked up in its file by a text script: where the name is declared,
and what its initializer is. The script reads text, not the program, so the buckets are close, not exact.

| Where the called function comes from | Sites | The phase that can answer |
|---|---|---|
| the result of a library hook: a zustand selector (`useProjectStore(s => s.x)`), `getState()`, `useCallback`, `useEffectEvent`, `useMemo`, `useRef` | ~154 | TC10 (a library function that returns its argument) for `useCallback` / `useEffectEvent`; a store's field is a library's value |
| a prop: a name of a destructured parameter (`function Dialog({ onClose }: Props)`) | 94 | TC4 |
| a project hook's result, taken apart (`const { refresh } = useConversations()`) | ~33 | TC4 and TC6 |
| a parameter of the function around (`createRafDispatcher(onFrames)` → its nested `flush` calls `onFrames`), or of a curried arrow | 9 | TC2 with TC3's captures |
| a local that is one of two values (`ReactIcon \|\| FallbackIcon`, `asChild ? Slot : "span"`) | 3 | TC3, but each holds a library component: no edge |
| another object's field (`tool.icon`, `face.ConfigForm`) and the rest | ~12 | TC4 / TC6 |

The counter's split (per context) was 172 from a call's result, 126 from a parameter, 29 from elsewhere: the 126 are mostly the 94
props, which the counter calls "from a parameter" because a destructured parameter is one.

**What it says.** The plan is not wrong: every bucket has a phase. TC3 answers at most about 10 of V-NOC's sites; its yield is in
imperative code (N4: 16% and 9% of the private codebase's and the compiler's capable locals are written more than once). For V-NOC the
phases that matter are TC4 (props) and TC10, which is not scheduled (D65: "later, with the counts of TC6").
