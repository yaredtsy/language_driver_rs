# Rust: the policy table

What the analyzer draws, and what it does not, for each feature of the language: the default resolver, layer 1 (RS4). **Every row names a
fixture** and the entries built from it. Changing a row is a policy change: the fixture and its snapshot change in the same commit, and the
version takes a minor step (`docs/01-monorepo/06-versions-and-vnoc.md`).

The plan is `docs/04-rust/04-default-resolver/05-rs4-calls.md` (§3 the sites, §4 the resolver, §5 the bridge, §6 this table); the
engine's side of each row (what rust-analyzer answers, and the numbers) is in `../ENGINE.md`. This file says what was built (RS4 steps
1–9b, reviewed by 2026-11-19).

**Where a row is checked.** The last cell of a row is read by a test (`crates/rust-analysis/tests/policy.rs`, to be built; TypeScript's
`typescript-analysis/tests/policy.rs` is the model), so it holds nothing but its words in backticks, in this grammar (the test reads the rows of this first table only, from its `| Row |` header to
the first line that is not a row; the counters table at the end is not read):

- **groups** separated by `; `;
- a group is a **workspace** (a folder under `crates/rust-analysis/tests/fixtures/`, which is also the root it is opened at: `owner/ws/app`
  opens at `ws/app`, the workspace above it loaded), then **one file** of it (relative to that root), then **the entries** in that file
  (qualnames; a second def of one name is `name#1`);
- a group that begins with a file keeps the workspace of the group before it;
- a cell that is **a folder alone** names the outline's fixtures (row `def`): no graph, no snapshot.

The test fails on a row with no fixture, a workspace or file that is not there, a file with no entry, an id used twice, a row without its
snapshot `crates/rust-analysis/tests/snapshots/policy/<row>.txt` and a snapshot of no row. A snapshot is, for each entry, a heading `== <file> <entry>`,
the tree (the project's defs), then every edge of the graph as `from | callee text | what it is` (sorted by the `from` def's name, byte
order, so `Rec::mk` before `by_type_alias`; in source order within one def; two sites with the same text are two lines), then
`counters: key=n, …` above 0 (`Stats.language`, the reasons of the `Unresolved` edges included); an entry that is no def (row `cfg-off`'s
`disabled`) is written `no def`. Built in 2e2e0f7 (reviewed 2026-11-20). Write the expected text by hand before running; bless only to write a snapshot you then
review. What else proves a row (a named test, a load forced down the ladder) is said in its policy cell, never in the last one.

The older snapshots stay, under `crates/rust-analysis/tests/snapshots/`: `sites/<file>.txt` (every site of every def of a `policy` file,
step A, §3), `callees/<file>.txt` (what each reaches, with its `open` kind, step B, §4), `trees/policy.txt` and `trees/context.txt` (the
entries `tests/common/mod.rs` lists), and `trees/open_counts.txt` (the `open_*` counts of those entries, frozen at D44).

The "Changed by" column names the context-layer phase that changes a row (`docs/04-rust/05-context-layer/`); each RC phase fills its own
rows' "precise" behaviour here when it is built.

## Reasons and counters

Every one is in `Graph.stats.language`, absent when 0, and printed by `Breakdown` (`rust-cli calls`). A **reason** is the reason of an
`Unresolved` edge (`Stats.unresolved` adds them up); a **note** is a count of what no edge shows; a **load** counter says what the load
left out.

| Key | Kind | Rows |
|---|---|---|
| `function_typed_value` | reason | `function-typed`, and since D44 a required trait method (`type-param`, `self-in-trait`, `dyn`, `impl-return`, `projection`, `trait-path`) |
| `unknown_callee`, `unknown_method` | reason | `unknown`, `no-std`, `proc-macro` |
| `def_not_in_outline` | reason | none: a bug flag (a project def the outline has no row for). Pinned at 0 on `core/` |
| `open_type_param`, `open_self_in_trait`, `open_impl_trait`, `open_projection`, `open_opaque`, `open_dyn`, `open_closure`, `open_fn_pointer`, `open_fn_param` | note | what the answer is a family of defs for, by why: the rows above, and the input of RC0. A site can be `open` and still have an edge (a default body) |
| `open_other` | note | a trait item whose cause was not classified (`Dispatch::Unclassified`). **No fixture: no known shape reaches it** in either workspace, and it is 0 on `core/`. A count above 0 on real code means the classification is missing a case |
| `macro_not_expanded` | note | `macro-not-expanded`, `no-std` |
| `macro_generated_target` | note | `macro-made-fn`, `derive` |
| `outside_root` | note | `outside-root` |
| `external_passed`, `constructor_passed`, `signature_passed` | note | `passed-no-edge` |
| `duplicate_marker` | note | `duplicate-marker` |
| `warning_<code>` | load | `no-std`: one per warning of the load (`cargo_failed`, `no_manifest`, `no_toolchain`, ...: `Warning::code`) |
| `build_scripts_skipped`, `proc_macros_skipped`, `layout_skipped` | load | `proc-macro`; `layout_skipped` when D37's reader could not follow a target layout |

`open_counts.txt` freezes the `open_*` counts of every policy and context entry: D44 changed what a required method is, not how open it
is. A phase that closes sites on purpose updates that file in its own commit (`docs/04-rust/05-context-layer/01-design.md` §11).
